# JPEG/PNG 文件元数据隐式标识工作简报

日期：2026-08-19

开发分支：`feature/image-metadata`

## 1. 工作范围

本次负责后端 JPEG/JPG、PNG 的 AIGC 文件元数据隐式标识适配器和测试，不包含前端页面、MP4、显式标识、内容水印及 C2PA 签名。

## 2. 完成内容

- 按 GB 45438—2025 附录 E 校验并写入外层 `AIGC` 对象和固定七字段。
- 使用 ExifTool 将完整 AIGC JSON 写入 JPEG/PNG 的 XMP，不覆盖原文件。
- 支持已有标识默认拒绝，以及用户明确确认后的整体替换。
- 写入后检查仅一份标识、字段逐项一致、Schema 正确、图片可解码且像素不变。
- 使用项目 XMP 读取器和 ExifTool 两条路径交叉回读。
- 增加 ProduceID 生成、异步任务创建、状态查询、结果下载及能力检查接口。
- 使用 SQLite 保存任务审计记录和编号唯一性记录。

## 3. 项目自行规定的实现

- ProduceID 默认使用后端生成的大写 UUID。
- 单机阶段使用 SQLite、本地隔离文件目录和线程池；默认并发数为 2。
- 单文件默认上限为 25 MiB，结果默认保留 168 小时，ExifTool 默认超时 30 秒。
- 图片载体标识为 `xmp-aigc-v1`，适配器版本为 `jpeg-png-xmp-exiftool-v1`。
- 支持 `Idempotency-Key` 防止重复提交；所有本地路径均通过环境变量配置。

以上属于项目实现选择，不是国标指定的唯一技术方案，后续可替换为集中式数据库、任务队列和对象存储，但公共 API 应保持稳定。

## 4. 验证结果

- 自动化测试：`104 passed`。
- 编译检查、Git 差异检查和 6 条必要 OpenAPI 路径检查通过。
- 人工完成“生成编号—正常写入—异步查询—下载—独立检测”闭环。
- 已有标识使用 `reject` 时正确返回 `AIGC_METADATA_EXISTS`。
- 使用 `replace` 后旧标识被整体替换，最终仍只有一份记录，新七字段回读正确。

## 5. 结论与边界

当前 JPEG/PNG 后端适配器、异步接口和测试已达到本阶段任务要求。现有综合检测报告中的 OCR 和水印警告属于仓库其他未启用模块，不影响本阶段 `metadata.schema: pass` 的验收结论。前端标注页面和 MP4 仍由后续任务完成。

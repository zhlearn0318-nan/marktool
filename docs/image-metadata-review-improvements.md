# 图片元数据模块代码评审修改与验收报告

日期：2026-08-21

开发分支：`feature/image-metadata`

范围：后端 JPEG/JPG、PNG 文件元数据隐式标识适配器、异步接口及测试

## 1. 修改结论

本轮针对《图片元数据模块代码评审意见》中的七项合入阻断问题完成加固。七项阻断要求均已处理，但其中 Extended XMP 和 SQLite 并发采用了评审意见明确允许的保守备选方案，而不是实现复杂度更高的完整能力。

本次没有修改前端、MP4、显式标识、像素水印、C2PA、原有 `/api/detect` 路由及其检测/报告核心，也没有合并主分支。这样可以保护仓库原有模块，避免把本阶段任务扩大到其他成员负责的范围。

## 2. 七项阻断问题对照

| 评审问题 | 处理结果 | 实际实现 |
|---|---|---|
| Extended XMP 绕过 `reject` | 已解决 | 写入前检测 Extended XMP；项目读取器与 ExifTool 交叉检查；结果不一致立即停止；增加字段和 JSON 长度上限 |
| 已发布结果在崩溃恢复时被判失败 | 已解决 | 增加 `publishing_output` 阶段；恢复时发现已有结果则重新回读、校验输入哈希与像素、登记编号并补写成功状态，绝不覆盖已有文件 |
| SQLite 编号事务导致多 Worker 锁等待 | 已解决（采用备选方案） | 首期固定 `worker_count=1`；异步接口仍可接收多个任务并依次排队；配置为其他值时拒绝启动 |
| ExifTool 健康检查假阳性 | 已解决 | 实际执行 `exiftool -ver`；校验配置可读、退出码及版本格式；假文件、超时、错误退出和异常输出均判为不可用 |
| 上传与解码资源限制不完整 | 已解决 | 单文件、完整请求、分块请求、宽高和总像素均设上限；处理 Pillow 解压炸弹；图片预检移出事件循环 |
| 409 响应不能支持前端展示 | 已解决 | `AIGC_METADATA_EXISTS` 返回安全摘要，包括份数、解析/Schema 状态及必要身份字段，不回显损坏的原始 XMP |
| 缺少真实 ExifTool CI 门禁 | 已解决 | GitHub Actions 固定 ExifTool 13.59；设置 `AIGC_REQUIRE_EXIFTOOL=1`，缺少真实工具时测试失败；保留真实 JPEG/PNG 端到端测试 |

## 3. 本轮具体改进

1. 写入前由项目 XMP 读取器和 ExifTool 交叉检查已有 AIGC 记录。
2. 检测到 JPEG Extended XMP 时返回 `EXTENDED_XMP_UNSUPPORTED`，不写入、不替换原文件。
3. 两种读取器结果不一致时返回 `AIGC_METADATA_INCONSISTENT`。
4. 七字段单项最多 1024 字符，完整 AIGC JSON 最多 8192 UTF-8 字节。
5. 单文件最多 25 MiB、完整 multipart 请求最多 27 MiB、单边最多 16384 像素、总像素最多 4000 万。
6. 处理 Pillow `DecompressionBombWarning` 和 `DecompressionBombError`，超限返回稳定的 413 错误。
7. 首期固定单工作线程，两个任务可以通过异步接口依次排队完成。
8. 增加结果发布后的中断恢复，恢复过程重新验证元数据、输入哈希和像素完整性。
9. 健康接口真实运行 ExifTool，并返回 `available` 和版本号。
10. 409 响应增加已有标识安全摘要。
11. FastAPI 退出时关闭默认任务服务线程池，耗时上传预检放入工作线程。
12. GitHub Actions 固定真实 ExifTool 13.59 并运行全部后端测试。

## 4. 没有按“更完整方案”实现的部分及原因

以下内容必须重点说明。它们并非遗漏七项阻断问题，而是选择了评审允许的备选做法，或属于评审中明确标为“不阻断本次合入”的生产增强。

### 4.1 没有实现 Extended XMP 分片组装

当前做法是检测到 Extended XMP 后明确拒绝 `reject` 和 `replace` 两种操作，而不是组装 Adobe Extended XMP 的全部 APP1 分片。

原因：完整支持需要处理 GUID、总长度、分片偏移、乱序、缺片、重复片及普通 XMP 与扩展 XMP 的引用关系，错误实现反而可能造成旧标识漏检或误覆盖。当前任务只要求 JPEG/PNG 国标七字段元数据闭环，评审意见也明确允许“支持或清楚拒绝”。因此首期选择安全拒绝，后续只有在补齐完整解析规范和恶意分片测试后才能开放支持。

影响：普通 JPEG/PNG 正常处理；含 Extended XMP 的 JPEG 返回专用错误，不会静默覆盖，但暂时不能直接为该文件写入或替换标识。

### 4.2 没有实现多 Worker 的短事务 provisional reservation

当前没有重构 SQLite 编号登记为“短事务预占 + provisional 状态”，而是固定 `worker_count=1`。

原因：短事务方案需要新增预占状态、租约过期、进程崩溃清理、幂等提交和数据库迁移，会显著增加首期单机模块的状态复杂度。评审意见明确允许首期设置为 1。单线程仍保持异步任务接口，多个请求可以排队，不会阻塞前端，也避免虚假的并发能力和 SQLite 锁超时。

影响：首期任务按顺序执行，吞吐量低于真正并行；后续切换 PostgreSQL/Redis 队列或设计完整预占协议后才能提高 Worker 数量。

### 4.3 没有配置反向代理层请求上限

本轮完成了应用层完整请求体限制，但没有添加 Nginx、Caddy 或云网关配置。

原因：仓库尚未确定正式部署平台和反向代理类型，直接加入某一种代理配置可能与团队部署方案冲突。应用层限制已经能在当前开发环境生效；正式部署时必须在选定的代理层设置不大于应用上限的请求限制。

### 4.4 没有开发前端展示页面

后端已经在 409 响应中返回已有标识安全摘要，但没有修改前端页面去展示摘要或弹出 `replace` 确认框。

原因：用户负责范围明确为后端 JPEG/PNG 元数据适配器和测试，前端由其他成员负责。直接修改前端容易覆盖或干扰其他成员工作。本次通过稳定接口契约和文档为前端提供接入条件。

### 4.5 没有加入账号鉴权、用户级权限、限流和下载鉴权

原因：这些属于评审中的非阻断生产增强，并且依赖团队尚未确定的账号体系、权限模型、部署网关和前端登录方式。当前擅自规定会造成接口不兼容。正式上线前必须由团队统一设计并补齐；当前接口只适合受控开发和联调环境。

### 4.6 没有收紧生产 CORS

当前仍保留仓库原有的开发期通配 CORS。

原因：正式前端域名、端口和部署环境尚未确定，而且本次原则是保护原有代码，不擅自改变现有前端访问行为。正式部署前必须将允许来源改成确定的域名白名单。

### 4.7 没有加入集中式结构化日志、指标和告警

原因：团队尚未选择日志/监控平台，也没有统一字段和数据保留策略。当前保留错误码、任务状态、阶段和 request ID 以支持开发排查；生产环境应在选定 Sentry、OpenTelemetry 或其他方案后补充耗时、失败率、ExifTool 和 SQLite 指标。

### 4.8 没有重构 HTTP 请求 ID 与任务关联 ID

轮询响应目前继续使用创建任务时的 `request_id`，没有额外引入每次 HTTP 调用独立的 `trace_id`。

原因：直接改变现有 `request_id` 语义会影响前端契约和已有测试。更合理的后续方案是保留稳定的任务关联 ID，同时新增每请求 trace ID，而不是在本轮破坏兼容性。

### 4.9 没有使用分布式队列、集中式数据库和对象存储

当前仍采用单机线程池、SQLite 和本地隔离文件目录。

原因：本阶段是可验证的 MVP 后端模块，尚无多机部署要求。上述替换需要团队统一选择 Redis/Celery、数据库和对象存储，并设计迁移与权限策略，不应由图片适配器分支单方面决定。

### 4.10 没有在每条任务公开响应中新增 ExifTool 版本字段

当前 CI 固定 ExifTool 13.59，健康接口公开实际版本，任务数据库继续记录适配器版本；没有为现有任务表和公共响应新增“每任务 ExifTool 版本”字段。

原因：这需要任务表迁移和公共 API 字段评审。首期已经通过固定 CI 版本和健康接口消除“工具身份未知”的主要风险；后续完善审计模型时应把实际工具版本固化到每条任务记录。

## 5. 项目自行约定

资源上限、字段长度、单线程执行、错误码、任务恢复阶段和 ExifTool 固定版本属于项目工程约定，不是 GB 45438—2025 指定的唯一数值或唯一实现。调整这些约定时，必须同步修改接口文档、环境变量说明和自动化测试。

## 6. 验证结果

### 6.1 自动化测试

本机使用真实 ExifTool 13.59 执行完整测试：`122 passed`，无失败、无跳过。覆盖：

- JPEG/PNG 真实写入、回读、下载与像素完整性；
- Extended XMP 的 `reject` 和 `replace` 安全拒绝；
- 双读取器分歧、重复记录和已有标识安全摘要；
- 字段、JSON、文件、完整请求、分块请求、尺寸和像素限制；
- Pillow 解码炸弹错误；
- 单线程双任务排队和已发布结果中断恢复；
- 真实、伪造、超时、错误退出及异常输出的 ExifTool 健康检查。

### 6.2 人工验收

- JPEG：完成正常写入、已有标识 `reject`、明确 `replace`、下载、`/api/detect` 独立检测及 ExifTool 唯一性计数；替换后 `Label=2`，新 ProduceID 回读正确，记录数为 1。
- PNG：完成写入、下载、`/api/detect` 独立检测及 ExifTool 唯一性计数；保持真实 `image/png`，尺寸 1728×1080，记录数为 1。
- JPEG 与 PNG 的 `read_back_succeeded`、`schema_valid`、`single_aigc_record`、`media_integrity_valid` 均为 `true`。

## 7. 最终边界与结论

本模块已达到当前“JPEG/PNG 文件元数据隐式标识后端适配器和测试”的合入条件。结论不代表整个平台已达到生产上线条件；第 4 节所列鉴权、生产 CORS、代理限制、可观测性和分布式架构等事项仍需团队在正式部署前完成。
